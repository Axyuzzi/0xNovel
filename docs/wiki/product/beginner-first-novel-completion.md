# 新手优先与整本小说完成原则

## 背景

项目的主要用户是完全写作新手。他们通常不知道如何设计结构、节奏、角色弧、伏笔、卷纲或章节任务单。产品不能假设用户能手动修复长篇结构问题，也不能把复杂专业判断抛给用户。

因此，产品目标不是提供零散写作工具，而是帮助用户从模糊灵感持续推进到完整小说。

## 决策

所有产品、UX、Prompt、Agent 和 runtime 决策优先服务“新手完成整本小说”。当专家灵活性和新手完成率冲突时，默认选择降低认知负担、给出强默认值和明确下一步的方案。

AI 应承担规划、判断、调度、执行、追踪和修复建议；确定性代码负责安全、幂等、输入校验、权限、状态落库和结构化输出后的处理。

## 当前规则

- 关键页面应告诉用户当前做到哪里、下一步是什么、为什么推荐这一步、风险影响哪些范围。
- 自动导演、章节生产和 Creative Hub 都应围绕整本完成主链，不新增无助于主链的复杂分支。
- 产品默认值应能让新手继续前进；高级选项不能阻塞基础流程。
- 自动导演里的读者频道倾向是 AI 上下文提示，不是确定性分流规则；默认应允许 AI 根据题材、卖点和起始想法自行判断。
- 面向空白输入框的灵感辅助应保持低耦合：可以临时生成参考文本、帮助用户破除空白页，但除非用户显式复制或手动粘贴，否则不得写入项目、任务、自动导演 seed payload 或任何长期资产。
- 外部世界库应展示为“可复用世界样本”，而不是原始字段表单。列表卡片应优先呈现世界概要、核心规则数量、势力数量、地点数量、关系数量，以及可被小说抽取的规则、舞台和冲突线索。
- 外部世界工作台的概览页应展示“世界手册”，优先回答这个世界是什么、有哪些必须遵守的规则、哪些势力推动冲突、故事会在哪里发生、哪些张力可被小说抽取。字段级编辑应留在结构化设定页，不应占据概览入口。
- 小说内世界应展示为“本书世界手册”，帮助用户理解这本书正在使用哪个世界、来源是什么、是否可同步，以及哪些规则会进入生成链。
- 小说页里“本书世界”负责创建、导入、生成和同步小说世界副本；“围绕这本书的世界边界”只负责确认这本书实际会使用哪些规则、势力和地点。两个入口不能都写成“绑定世界观”，否则新手无法理解外部样本、本书副本和生成链裁剪的区别。
- 本书世界入口应提供三种低认知负担路径：从世界库导入、根据本书主题生成、自定义本书世界。自定义入口创建最小世界手册，不要求新手先填完复杂字段。
- 旧 `worldId` 下拉只作为兼容字段或自动导演快速参考。面向用户的主世界管理入口必须是“本书世界”，后续功能不要继续把旧下拉扩展成世界管理中心。
- 世界地图、势力图谱、时间线和力量体系图应作为“世界资产”展示在世界手册旁边。它们的作用是帮助新手看见世界，而不是要求用户先理解数据表字段。
- 世界资产入口可以先以“待生成”的方式出现，但文案要说明资产能帮助整理区域、势力关系和力量边界，不能只显示技术性的 Coming Soon。
- 失败后应提供可恢复路径、局部影响范围和下一步建议，不只显示错误。
- UI 文案从用户视角写功能和下一步，不写实现迁移、架构变化或“我们改了什么”。
- 质量判断、下一步推荐和修复路径应通过 AI-first 结构化理解完成。
- 对会影响后续 AI 规划的可视化编辑，默认应拆成“只读理解层”和“显式编辑层”。例如紧张度曲线在工作台和卷战略页只展示当前走势、锚定状态、参考线和形状提示；拖拽、单点/批量交还 AI、章节细节对照等写入能力只放在明确打开的编辑弹窗里。
- 写入型编辑层必须先给用户足够的叙事上下文，再让用户调整数值。紧张度曲线编辑应同时展示卷级定位、当前节奏段摘要、必须交付项和选中章节摘要，避免新手只围绕孤立数字做决策。
- 自动导演新书创建应采用“渐进式但不强制线性”的流程：首屏只要求起始想法，并且应被设计成一个安静的开场提问，而不是表单第一页。后续再展开导演起始设置、世界与写法、模型与运行方式、方向候选。已经确认的阶段应折叠成可点击摘要，方便回改；熟练用户可以在起始想法后直接用默认设置生成方向。
- 自动导演首屏的灵感参考只能作为按需辅助出现。默认视觉中心必须是起始想法输入框；灵感示例不应以大面积卡片、密集边框或多列窄排抢走主输入的层级。
- 自动导演这类分阶段创建流程的阶段摘要应使用轻量进度轨道或紧凑摘要，不应把每个阶段做成等视觉重量的卡片。阶段摘要的作用是定位和回改，不是和当前舞台争夺注意力。
- 自动导演后续设置阶段也应延续“舞台式确认”而不是“表单页”心智。世界与写法、模型与运行方式这类步骤可以展示必要选项，但分组应主要依靠标题、说明、留白和浅底色；只有互斥决策才使用选择块，不能把每段说明都包成边框卡片。

## 示例

推荐做法：

- 自动导演面板显示当前阶段、等待确认点、可自动审批项和写入范围。
- 自动导演创建页先让用户写一句灵感，再逐步确认少量高影响设置；读者频道、叙事视角、节奏、情绪浓度、世界处理、写法资产和运行方式都应有默认值，不能要求用户先懂完整小说策划。
- 起始想法页可以提供“没有想法？看几个开头”，但灵感应以横向可读的行式列表出现，用户选择后填入输入框并继续可编辑，而不是让用户先阅读一组厚重推荐卡。
- 导演起始设置页应把“确认手感”放在主标题层级，表单字段用浅底色和留白组织；书级 framing 可以作为同一舞台内的轻量分组，不应再形成卡片套卡片。
- 世界与写法页应把“选择参考世界样本”和“确认本书写法”处理成低压力确认：有世界样本时展示它会如何进入导演上下文，没有样本时提供“自动整理本书世界 / 暂不使用世界观”的明确二选一。模型与运行方式页应强调这是启动前最后确认，运行模式选择比模型说明更靠近主决策。
- 章节执行显示“正文可读”“资产回灌中”“账本校准中”等不同状态，让用户先看正文，再观察后台同步。
- Creative Hub 回答小说进展时，先说明真实产物进度，再补充后台任务情况和推荐下一步。
- 世界库卡片显示“力量与规则”“势力舞台”“故事发生地”“可抽取的冲突线”，让新手先判断这个世界能不能支撑一部小说，再进入工作台编辑细节。
- 世界工作台概览页显示“力量与规则”“主要势力”“故事舞台”“关键张力”“小说生成时应优先遵守”，让用户把世界当成故事环境理解，而不是当成数据库字段检查。
- 小说页的本书世界卡片显示“来源”“生成链”“同步”三类状态，让用户知道当前世界从哪里来、是否会进入角色/大纲/章节生成、是否会与世界库发生手动同步。
- 本书世界卡片同时提供“从世界库导入”“自定义本书世界”“生成本书世界”，让用户先建立本书副本，再逐步完善世界手册和边界。
- 本书世界手册旁边展示“世界地图”“势力图谱”“世界时间线”“力量体系树”等世界资产入口，用短说明告诉用户这些资产会解决什么理解问题。
- 基础信息和自动导演中的旧世界选择文案应写成“世界样本”或“参考世界”，并提示完整导入、生成和同步在“本书世界”完成。
- 节奏 / 拆章工作台的紧张度曲线主视图只解释结果；如果用户要调整强度，应进入编辑弹窗，并在卷级定位、节奏段交付和章节摘要旁边完成拖拽或交还 AI。

## 统一自适应首页

首页采用一套稳定结构，根据用户当前状态自动改变核心内容，不为新用户和老用户维护两套独立首页。

这项决策的目标是：

- 用户只需要学习一套导航和页面结构。
- 新用户打开首页时立即开始第一个故事，不先阅读仪表盘。
- 老用户打开首页时立即继续最近作品，不重复经历新手教程。
- 生成、失败、离线和余额不足都在同一首页语境中表达，不把用户送到技术任务页面。

### 顶层导航

普通用户的顶层导航固定收敛为：

1. 首页
2. 我的作品
3. 素材
4. 我的

“创作”发生在具体作品内部，不作为独立顶层导航。“任务中心”“模型路由”“Prompt”“运行日志”等专业入口不进入普通用户主导航；后续如保留专家能力，应放在明确的高级入口中。

### 首页状态优先级

首页每次进入时读取本地作品、最近操作、运行任务、登录、网络和余额状态，按照以下优先级选择一个主要动作：

1. 有需要恢复的生成任务：优先显示继续、重试或查看已完成结果。
2. 有最近作品：优先显示继续创作最近作品。
3. 没有任何作品：显示一句故事想法输入和新手创建入口。

余额不足和离线属于能力状态，不应覆盖用户的作品上下文。它们通过轻量提示说明哪些操作暂不可用，用户仍可查看和编辑本地作品。

| 用户状态 | 首页核心内容 | 唯一主动作 |
|---|---|---|
| 首次登录且没有作品 | “你想写一个什么故事？”、一句想法输入、题材与随机灵感辅助 | 帮我完善这个故事 |
| 已有作品且当前没有任务 | 最近作品、上次创作位置、推荐下一步 | 继续创作 |
| 第一章或后续章节生成中 | 当前作品、可理解的生成阶段和已保存进度 | 查看创作进度 |
| 任务中断或失败 | 已保留的结果、影响范围和恢复建议 | 继续或重试当前步骤 |
| 余额不足 | 保留原有作品与编辑入口，说明 AI 暂不可用 | 保持当前主动作，触发 AI 后再“充值并继续” |
| 离线且有历史身份 | 最近本地作品和离线说明 | 继续本地编辑 |

### 新用户首页

视觉中心固定为：

> 你想写一个什么故事？

主要输入是“一句话描述你的故事”。辅助入口只包括：

- 从热门题材开始。
- 帮我随机想一个。
- 查看少量灵感示例。

统计卡片、资产健康、模型状态、任务数量、运行指标和余额不能抢占首屏主层级。

### 老用户首页

视觉中心固定为最近一次可继续的创作现场：

> 继续创作《作品名称》

首页应展示：

- 上次写到的章节。
- 当前作品处于什么阶段。
- 系统推荐的下一步和原因。
- 一个最突出的“继续创作”按钮。

“打开最近章节”和“创建新作品”作为次要动作，不与主动作争夺视觉层级。

### 账户和余额表达

余额作为弱信息放在头像或“我的”附近，使用“创作余额”这类用户语言。首页不展示 Token、Quota、倍率、模型内部名称或底层计量单位。

余额为零不阻止进入首页、查看作品和本地编辑；用户真正触发付费 AI 操作时，再进入充值并在支付完成后返回原步骤。

### 验收规则

- [ ] 新用户和老用户使用同一个首页路由与同一套导航结构。
- [ ] 首页任一状态只有一个视觉上最突出的主动作。
- [ ] 无作品用户无需寻找“创建项目”，可以直接输入故事想法。
- [ ] 有作品用户启动后可以一次操作回到最近创作现场。
- [ ] 生成中、失败、离线和余额不足都不暴露内部任务或技术术语。
- [ ] 普通用户顶层导航只有“首页 / 我的作品 / 素材 / 我的”。
- [ ] 余额和账户信息不抢占创作主任务。

## 单作品文档型创作台

用户进入某一本作品后，默认工作区不是“小说生产控制台”，而是“带有智能作品目录的文本编辑器”。

默认布局遵循三个稳定职责：

```text
左侧作品目录 -> 选择正在查看或编辑的内容
中间内容编辑器 -> 阅读、写作和修改正文或作品资料
右侧 AI 抽屉 -> 只在需要时提供与当前内容相关的帮助
```

自动导演、AI 修复、质量债务、任务队列、审批点、上下文装配和资产回灌等原有专业能力继续保留，但默认作为后台引擎运行，不再平铺成普通用户需要理解和判断的按钮。

### 左侧作品目录

左侧按用户理解的作品内容组织，而不是按后端模块或生产流水线组织。

默认分组和顺序：

1. 正文
   - 按卷折叠章节。
   - 默认展开当前卷并定位到最近章节。
2. 故事规划
   - 作品方向。
   - 全书大纲。
   - 分卷安排。
   - 当前卷规划。
3. 角色
   - 主要角色。
   - 配角。
   - 角色关系。
4. 世界
   - 世界简介。
   - 核心规则。
   - 势力。
   - 地点。
5. 更多资料
   - 伏笔与线索。
   - 写作素材。
   - 历史版本。
   - 高级设置。

“正文”始终位于最上方，因为继续阅读和写作是打开作品后的最高频任务。世界设定的复杂度根据题材自适应：都市、现实和弱设定题材不要求用户先维护完整世界观。

左侧不能把世界规则、角色资源、质量债务、任务运行、章节合同等所有内部资产平铺成十几个一级项目。低频内容必须分组折叠，专业能力进入高级入口。

### 中间统一内容编辑器

用户从左侧选择任何内容，中间区域都保持“打开一份作品文档”的一致心智：

- 选择章节：阅读和编辑正文。
- 选择作品方向或全书大纲：阅读和编辑故事规划。
- 选择某一卷：阅读和编辑卷规划。
- 选择某个角色：阅读和编辑用户可理解的角色资料。
- 选择世界规则、势力或地点：阅读和编辑对应设定。

不同内容可以使用适合自身的数据结构，但必须共享稳定的页面骨架、保存反馈、历史恢复和 AI 入口。不能让章节、大纲、角色和世界分别变成四套完全不同的后台管理系统。

编辑器至少提供：

- 清晰的当前文档标题和所属位置。
- 自动保存状态。
- 本地保存失败提示与恢复动作。
- 撤销、重做和历史版本。
- 当前内容字数或必要的轻量摘要。

### 右侧按需 AI 抽屉

AI 助手默认可以收起，打开后根据中间正在编辑的内容提供少量上下文动作。

正文场景：

- 继续写。
- 修改选中内容。
- 润色。
- 扩写或缩写。
- 检查前后矛盾。

大纲场景：

- 完善大纲。
- 调整故事节奏。
- 补充冲突。
- 根据大纲规划分卷。

角色场景：

- 完善角色。
- 检查人物动机。
- 设计或梳理角色关系。

世界场景：

- 完善世界规则。
- 检查设定冲突。
- 补充势力、地点或故事舞台。

普通用户不需要判断应该打开自动导演、Creative Hub、AI 修复还是质量工作台。系统根据当前内容选择内部能力，对外统一表达为“AI 帮我写”。

### AI 内容写入边界

AI 不得在用户无感知的情况下直接覆盖现有正文、大纲、角色或世界资料。

统一写入规则：

- 第一次生成尚不存在的章节或资料时，输出写入新的草稿版本。
- 对已有内容执行润色、改写、扩写、缩写或修复时，先生成建议稿。
- 用户明确选择“采用”后，建议稿才替换或插入当前内容。
- 每次采用 AI 修改前自动创建可恢复版本。
- 放弃建议稿不会改变当前文档。
- 后台自动导演可以维护结构化状态，但不能静默重写用户正在编辑的正文。

用户选中一段内容后，显示轻量上下文动作：

- 润色。
- 改写。
- 扩写。
- 缩写。
- 检查问题。

AI 结果至少提供：

- 替换原文。
- 插入到下方。
- 重新生成。
- 放弃。

“继续写”生成的内容先作为当前章节的新草稿片段展示。用户采用后进入当前正文；在采用前关闭页面或发生异常，系统应保留可恢复草稿，不得覆盖原文。

整章重生成属于高影响、可能重复计费的操作，执行前必须说明：

- 原版本会保留。
- 本次将产生新的 AI 消费。
- 新结果会成为独立版本。
- 用户可以恢复旧版本。

首次生成、续写、局部改写和整章重生成都必须使用幂等请求，避免重复点击或网络重试导致重复结果和重复扣费。

验收规则：

- [ ] AI 修改已有内容前始终提供建议稿或差异预览。
- [ ] 用户未点击“采用”时，当前正式内容保持不变。
- [ ] 采用 AI 内容前自动创建历史版本。
- [ ] 第一次生成的章节保存为可编辑草稿。
- [ ] 续写草稿在页面关闭或中断后可以恢复。
- [ ] 整章重生成明确提示版本保留和新增消费。
- [ ] 重新生成不会删除用户可恢复的旧版本。
- [ ] 后台任务不能静默覆盖用户正在编辑的正文。
- [ ] 重复提交和网络重试不会重复扣费。

### 逐章确认与阶段审校

C 端默认不要求用户在每章生成后处理审校、修复、质量债务和导演消息。每章完成后的主流程只保留阅读、修改和继续创作。

每章生成后静默完成：

- 正文非空、截断、异常格式和保存状态等确定性基础校验。
- 当前章节版本保存。
- 下一章所需事实和连续性状态准备。
- 人物、世界、伏笔等资产增量同步或建立可恢复的后台同步任务。

这些动作不形成用户待办。深度 AI 审校默认不放在单章热路径中，由用户在剧情阶段或整卷结束时决定是否执行。

#### 默认方式：逐章确认

第一章生成完成后，编辑器底部只突出：

> 这章可以，继续写第二章

用户点击后：

1. 将当前版本保存为下一章的创作基线。
2. 准备下一章必需的事实和连续性状态。
3. 自动准备并生成下一章。
4. 用户停留在同一个创作台，不跳转到任务、审核或消息页面。

“这章可以”不锁死章节，用户以后仍可回来修改。它只表示后续生成以当前版本为依据。

辅助操作只包括“我想先修改”和按需打开“AI 帮我改”。

#### 可选方式：连续创作

用户可以在继续创作时选择“连续写到这一段剧情结束”。系统逐章执行生成、基础校验、保存和状态闭合，到达当前剧情阶段边界后自动暂停。

连续创作期间只突出“暂停创作”。暂停、断网、余额不足或关闭软件时必须保留已经完成的章节和当前可恢复进度。

连续创作不能默认跨越剧情阶段或整卷边界，也不能在用户无感知时无限生成和消费。

#### 费用提示与消费上限

逐章确认时，“继续写下一章”附近只显示下一章的预计消费范围。用户不需要理解 Token、模型倍率或内部计量单位。

连续创作开始前必须展示：

- 预计生成章数范围。
- 预计总消费范围。
- 本次连续创作的最大消费上限。
- 自动停止位置。

示例：

> 预计生成 4～6 章，预计消费 ¥2.80～¥4.50。达到 ¥5.00 或完成这一段剧情后自动暂停。

系统提供推荐上限，用户可以调整后点击一次“确认并开始”。最大消费上限必须由运行时强制执行，不能只是前端提示。

统一规则：

- 逐章确认只授权下一章及其必要状态同步的消费。
- 连续创作只授权当前剧情阶段和用户确认的最高金额。
- 达到消费上限后，在发起下一笔付费调用前暂停。
- 余额不足时保存当前章节和恢复位置，充值成功后返回原运行继续。
- 剧情阶段或整卷审校属于新的付费操作，必须单独展示预计费用并由用户确认。
- 后台必要的状态抽取和资产同步计入当前创作操作的总消费，不能形成没有上限的隐藏调用。
- 正常重试和网络恢复复用原幂等请求，不重复扣费。
- 用户明确要求重新生成时创建新的消费尝试，并再次说明费用。
- 完成、暂停或中断后展示本次实际总消费。

如果中转站尚不能提供稳定的人民币价格换算和请求级实际扣费，连续创作不得以无法执行的预计金额承诺上线；必须先冻结币种、价格和消费汇总契约。

#### 剧情阶段和卷末审校

到达当前节奏段时，面向普通用户表达为：

> 这一段剧情已经完成。

提供：

- 检查这一段剧情后继续。
- 暂不检查，直接继续。

卷末表达为：

> 第一卷已经完成。

提供：

- 检查本卷并准备下一卷。
- 跳过检查，直接开始下一卷。

阶段审校统一检查多章连贯性、人物行为、世界规则、节奏、重复、伏笔和下一阶段承接。检查结果收敛成整体结论、具体位置和一个推荐动作，不拆成多个需要用户调度的修复任务。

#### 创作进度边界

原“创作消息”不再承担必需操作。它改为只读的“创作进度”，记录章节完成、生成中断、阶段完成、暂停和恢复等历史。

真正需要用户确认的动作必须出现在当前正文或阶段结束位置，不能要求用户前往消息列表寻找不可点击的状态。

验收规则：

- [ ] C 端默认生成计划不在每章后强制启动深度 AI 审校。
- [ ] 每章完成后只有一个“确认当前章并继续下一章”的主动作。
- [ ] 用户确认章节后不离开当前创作台。
- [ ] 连续创作只运行到当前剧情阶段结束。
- [ ] 连续创作开始前展示预计章数、预计总消费和可执行的消费上限。
- [ ] 达到消费上限后不会发起新的付费调用。
- [ ] 阶段或卷末审校单独展示预计费用并由用户确认。
- [ ] 完成、暂停或中断后可以查看本次实际总消费。
- [ ] 剧情阶段和卷末都允许用户选择检查或跳过。
- [ ] 跳过阶段审校不会伪装成错误或产生待处理消息。
- [ ] “创作进度”中的历史状态不承担必需操作。
- [ ] 所有必要确认都在对应章节或阶段结束位置完成。

### 顶部操作

作品创作台顶部默认只保留：

- 返回首页。
- 当前作品名称。
- 自动保存状态。
- “AI 帮我写”。
- 更多。

“更多”可以承载导出、作品设置、历史版本和高级入口。生成、修复、跟踪、重规划、执行、审校和模型状态不得同时平铺在顶部。

### 专业状态的 C 端表达

| 内部能力或状态 | 普通用户表达 |
|---|---|
| AI 修复 | 帮我修改 |
| 自动导演跟踪 | AI 正在维护故事一致性 |
| 质量债务 | 发现需要检查的内容 |
| 任务中心 | 创作进度 |
| 重规划 | 调整故事方向 |
| 审批点 | 低风险自动继续，高影响变化才请求确认 |
| 运行日志 | 默认隐藏，需要诊断时导出 |
| Prompt 和模型路由 | 默认隐藏在高级设置 |
| 资产回灌 | 作品资料已同步 |
| Checkpoint | 已自动保存 |

状态主要用于说明发生了什么，不能把每一种状态都做成要求用户判断的操作按钮。任一时刻只给出一个推荐主动作；局部质量问题不能伪装成整本小说失败。

### 状态适配

| 作品状态 | 创作台默认表现 |
|---|---|
| 尚未生成第一章 | 中间显示开篇准备结果和“开始写第一章” |
| 正在生成章节 | 中间逐步展示正文和通俗生成阶段 |
| 章节已完成 | 打开正文编辑器，推荐“继续写下一章” |
| 生成中断 | 保留现有正文，只显示一个恢复主动作 |
| 离线 | 正常编辑本地内容，AI 抽屉说明联网后可用 |
| 余额不足 | 正常编辑，触发 AI 操作时充值并返回原位置 |

### 验收规则

- [ ] 用户进入作品后默认看到正文目录和内容编辑器，不先看到状态控制台。
- [ ] 左侧一级分组不超过“正文 / 故事规划 / 角色 / 世界 / 更多资料”。
- [ ] 章节、大纲、分卷、角色和世界资料共享一致的文档编辑骨架。
- [ ] AI 助手可以收起，并根据当前内容提供上下文动作。
- [ ] 普通用户界面不出现自动导演跟踪、质量债务、Checkpoint、Prompt、模型路由等内部术语。
- [ ] 顶部不形成生成、修复、跟踪、审校和重规划按钮墙。
- [ ] 原有专业能力仍可由后台调用，并保留高级或诊断入口。
- [ ] 任一作品状态只有一个推荐主动作。

## 禁止做法

- 要求新手自己判断是否应该重规划、修章节、重跑角色或修改世界观。
- 给用户展示内部重构、迁移或历史实现叙述作为产品说明。
- 把 Creative Hub 扩展成泛聊天工具，而不推进小说完成。
- 在世界库列表直接堆叠地理、文化、宗教、经济、历史等长字段，迫使用户像审表格一样理解世界。
- 在世界工作台概览页重复结构化设定页的表单和长文本编辑区，让用户无法区分“理解世界”和“维护字段”。
- 在小说页继续使用“绑定世界观”作为主入口，把外部世界库样本、本书世界副本和 StoryWorldSlice 裁剪结果混成一个概念。
- 在生成注入提示中继续写“未绑定世界观”，让用户误以为没有选择旧下拉就无法生成；正确表达应是“没有可用的本书世界上下文，生成会先根据小说基础信息推进”。

## 失败模式

- 用户看到很多按钮但不知道下一步：检查是否缺少单一推荐动作和原因。
- 用户以为任务卡住：检查前端是否展示真实产物进度、阻塞原因和恢复动作。
- 世界观参与生成链很弱：检查世界库样本、小说世界副本、StoryWorldSlice 和 `WorldContextGateway` 是否被清楚区分，生成链是否绕过了统一门面。
- 角色生成需要给新手一个低成本控制点：默认基于本书世界生成，同时允许选择势力倾向和世界规则合规检查，而不是要求用户手写完整人物背景。
- 可视化曲线一进入页面就能拖拽：这会把“浏览走势”误变成“写入锚定”，应改为只读展示 + 显式编辑入口，并为编辑现场补齐叙事上下文。
- 自动导演创建被做成弹窗套弹窗：方向候选、修订和执行进度需要足够纵向空间，也需要刷新后恢复同一现场；应使用独立页面和任务参数，而不是继续把长流程塞进创建表单弹窗。
- AI 判断失败后加了关键词兜底：应修 AI schema、prompt、上下文和评估，而不是让产品逻辑退回硬编码。
