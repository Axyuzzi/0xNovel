# 新手优先与整本小说完成原则

## 背景

项目的主要用户是完全写作新手。他们通常不知道如何设计结构、节奏、角色弧、伏笔、卷纲或章节任务单。产品不能假设用户能手动修复长篇结构问题，也不能把复杂专业判断抛给用户。

因此，产品目标不是提供零散写作工具，而是帮助用户从模糊灵感持续推进到完整小说。

## 决策

所有产品、UX、Prompt、Agent 和 runtime 决策优先服务“新手完成整本小说”。当专家灵活性和新手完成率冲突时，默认选择降低认知负担、给出强默认值和明确下一步的方案。

AI 应承担规划、判断、调度、执行、追踪和修复建议；确定性代码负责安全、防重复点击、输入校验、权限、状态落库和结构化输出后的处理。外部 AI 请求是否具备严格幂等能力，以中转接口契约为准。

## 当前规则

- 关键页面应告诉用户当前做到哪里、下一步是什么、为什么推荐这一步、风险影响哪些范围。
- 自动导演、章节生产和 Creative Hub 都应围绕整本完成主链，不新增无助于主链的复杂分支。
- 产品默认值应能让新手继续前进；高级选项不能阻塞基础流程。
- 自动导演里的读者频道倾向是 AI 上下文提示，不是确定性分流规则；默认应允许 AI 根据题材、卖点和起始想法自行判断。
- 面向空白输入框的灵感辅助应保持低耦合：可以临时生成参考文本、帮助用户破除空白页，但除非用户显式复制或手动粘贴，否则不得写入项目、任务、自动导演 seed payload 或任何长期资产。
- 外部世界库应展示为“可复用世界样本”，而不是原始字段表单。列表卡片应优先呈现世界概要、核心规则数量、势力数量、地点数量、关系数量，以及可被小说抽取的规则、舞台和冲突线索。
- 外部世界工作台的概览页应展示“世界手册”，优先回答这个世界是什么、有哪些必须遵守的规则、哪些势力推动冲突、故事会在哪里发生、哪些张力可被小说抽取。字段级编辑应留在结构化设定页，不应占据概览入口。
- 小说内世界应展示为“本书世界手册”，帮助用户理解这本书正在使用哪个世界、来源是什么、是否可同步，以及哪些规则会进入生成链。
- 小说页里“本书世界”负责创建、导入、生成和同步小说世界副本；“围绕这本书的世界边界”只负责确认这本书实际会使用哪些规则、势力和地点。两个入口不能都写成“绑定世界观”，否则新手无法理解外部样本、本书副本和生成链裁剪的区别。
- 本书世界入口应提供三种低认知负担路径：从世界库导入、根据本书主题生成、自定义本书世界。自定义入口创建最小世界手册，不要求新手先填完复杂字段。
- 旧 `worldId` 下拉只作为兼容字段或自动导演快速参考。面向用户的主世界管理入口必须是“本书世界”，后续功能不要继续把旧下拉扩展成世界管理中心。
- 世界地图、势力图谱、时间线和力量体系图应作为“世界资产”展示在世界手册旁边。它们的作用是帮助新手看见世界，而不是要求用户先理解数据表字段。
- 世界资产入口可以先以“待生成”的方式出现，但文案要说明资产能帮助整理区域、势力关系和力量边界，不能只显示技术性的 Coming Soon。
- 失败后应提供可恢复路径、局部影响范围和下一步建议，不只显示错误。
- UI 文案从用户视角写功能和下一步，不写实现迁移、架构变化或“我们改了什么”。
- 质量判断、下一步推荐和修复路径应通过 AI-first 结构化理解完成。
- 对会影响后续 AI 规划的可视化编辑，默认应拆成“只读理解层”和“显式编辑层”。例如紧张度曲线在工作台和卷战略页只展示当前走势、锚定状态、参考线和形状提示；拖拽、单点/批量交还 AI、章节细节对照等写入能力只放在明确打开的编辑弹窗里。
- 写入型编辑层必须先给用户足够的叙事上下文，再让用户调整数值。紧张度曲线编辑应同时展示卷级定位、当前节奏段摘要、必须交付项和选中章节摘要，避免新手只围绕孤立数字做决策。
- 自动导演新书创建应采用“渐进式但不强制线性”的流程：首屏只要求起始想法，并且应被设计成一个安静的开场提问，而不是表单第一页。后续再展开导演起始设置、世界与写法、模型与运行方式、方向候选。已经确认的阶段应折叠成可点击摘要，方便回改；熟练用户可以在起始想法后直接用默认设置生成方向。
- 自动导演首屏的灵感参考只能作为按需辅助出现。默认视觉中心必须是起始想法输入框；灵感示例不应以大面积卡片、密集边框或多列窄排抢走主输入的层级。
- 自动导演这类分阶段创建流程的阶段摘要应使用轻量进度轨道或紧凑摘要，不应把每个阶段做成等视觉重量的卡片。阶段摘要的作用是定位和回改，不是和当前舞台争夺注意力。
- 自动导演后续设置阶段也应延续“舞台式确认”而不是“表单页”心智。世界与写法、模型与运行方式这类步骤可以展示必要选项，但分组应主要依靠标题、说明、留白和浅底色；只有互斥决策才使用选择块，不能把每段说明都包成边框卡片。

## 示例

推荐做法：

- 自动导演面板显示当前阶段、等待确认点、可自动审批项和写入范围。
- 自动导演创建页先让用户写一句灵感，再逐步确认少量高影响设置；读者频道、叙事视角、节奏、情绪浓度、世界处理、写法资产和运行方式都应有默认值，不能要求用户先懂完整小说策划。
- 起始想法页可以提供“没有想法？看几个开头”，但灵感应以横向可读的行式列表出现，用户选择后填入输入框并继续可编辑，而不是让用户先阅读一组厚重推荐卡。
- 导演起始设置页应把“确认手感”放在主标题层级，表单字段用浅底色和留白组织；书级 framing 可以作为同一舞台内的轻量分组，不应再形成卡片套卡片。
- 世界与写法页应把“选择参考世界样本”和“确认本书写法”处理成低压力确认：有世界样本时展示它会如何进入导演上下文，没有样本时提供“自动整理本书世界 / 暂不使用世界观”的明确二选一。模型与运行方式页应强调这是启动前最后确认，运行模式选择比模型说明更靠近主决策。
- 章节执行显示“正文可读”“资产回灌中”“账本校准中”等不同状态，让用户先看正文，再观察后台同步。
- Creative Hub 回答小说进展时，先说明真实产物进度，再补充后台任务情况和推荐下一步。
- 世界库卡片显示“力量与规则”“势力舞台”“故事发生地”“可抽取的冲突线”，让新手先判断这个世界能不能支撑一部小说，再进入工作台编辑细节。
- 世界工作台概览页显示“力量与规则”“主要势力”“故事舞台”“关键张力”“小说生成时应优先遵守”，让用户把世界当成故事环境理解，而不是当成数据库字段检查。
- 小说页的本书世界卡片显示“来源”“生成链”“同步”三类状态，让用户知道当前世界从哪里来、是否会进入角色/大纲/章节生成、是否会与世界库发生手动同步。
- 本书世界卡片同时提供“从世界库导入”“自定义本书世界”“生成本书世界”，让用户先建立本书副本，再逐步完善世界手册和边界。
- 本书世界手册旁边展示“世界地图”“势力图谱”“世界时间线”“力量体系树”等世界资产入口，用短说明告诉用户这些资产会解决什么理解问题。
- 基础信息和自动导演中的旧世界选择文案应写成“世界样本”或“参考世界”，并提示完整导入、生成和同步在“本书世界”完成。
- 节奏 / 拆章工作台的紧张度曲线主视图只解释结果；如果用户要调整强度，应进入编辑弹窗，并在卷级定位、节奏段交付和章节摘要旁边完成拖拽或交还 AI。

## 统一自适应首页

首页采用一套稳定结构，根据用户当前状态自动改变核心内容，不为新用户和老用户维护两套独立首页。

这项决策的目标是：

- 用户只需要学习一套导航和页面结构。
- 新用户打开首页时立即开始第一个故事，不先阅读仪表盘。
- 老用户打开首页时立即继续最近作品，不重复经历新手教程。
- 生成、失败、离线和余额不足都在同一首页语境中表达，不把用户送到技术任务页面。

### 顶层导航

普通用户的顶层导航固定收敛为：

1. 首页
2. 我的作品
3. 素材
4. 我的

“创作”发生在具体作品内部，不作为独立顶层导航。“任务中心”“模型路由”“Prompt”“运行日志”等专业入口不进入普通用户主导航；后续如保留专家能力，应放在明确的高级入口中。

### 首页状态优先级

首页每次进入时读取本地作品、最近操作、运行任务、登录、网络和余额状态，按照以下优先级选择一个主要动作：

1. 有需要恢复的生成任务：优先显示继续、重试或查看已完成结果。
2. 有最近作品：优先显示继续创作最近作品。
3. 没有任何作品：显示一句故事想法输入和新手创建入口。

余额不足和离线属于能力状态，不应覆盖用户的作品上下文。它们通过轻量提示说明哪些操作暂不可用，用户仍可查看和编辑本地作品。

| 用户状态 | 首页核心内容 | 唯一主动作 |
|---|---|---|
| 首次登录且没有作品 | “你想写一个什么故事？”、一句想法输入、题材与随机灵感辅助 | 帮我完善这个故事 |
| 已有作品且当前没有任务 | 最近作品、上次创作位置、推荐下一步 | 继续创作 |
| 第一章或后续章节生成中 | 当前作品、可理解的生成阶段和已保存进度 | 查看创作进度 |
| 任务中断或失败 | 已保留的结果、影响范围和恢复建议 | 继续或重试当前步骤 |
| 余额不足 | 保留原有作品与编辑入口，说明 AI 暂不可用 | 保持当前主动作，触发 AI 后再“充值并继续” |
| 离线且有历史身份 | 最近本地作品和离线说明 | 继续本地编辑 |

### 新用户首页

视觉中心固定为：

> 你想写一个什么故事？

主要输入是“一句话描述你的故事”。辅助入口只包括：

- 从热门题材开始。
- 帮我随机想一个。
- 查看少量灵感示例。

统计卡片、资产健康、模型状态、任务数量、运行指标和余额不能抢占首屏主层级。

### 老用户首页

视觉中心固定为最近一次可继续的创作现场：

> 继续创作《作品名称》

首页应展示：

- 上次写到的章节。
- 当前作品处于什么阶段。
- 系统推荐的下一步和原因。
- 一个最突出的“继续创作”按钮。

“打开最近章节”和“创建新作品”作为次要动作，不与主动作争夺视觉层级。

### 账户和余额表达

余额作为弱信息放在头像或“我的”附近，统一显示“0x积分余额”。首页不展示 Token、Quota、倍率、模型内部名称或底层计量单位。

余额为零不阻止进入首页、查看作品和本地编辑；用户真正触发付费 AI 操作时，再进入充值并在支付完成后返回原步骤。

### 验收规则

- [ ] 新用户和老用户使用同一个首页路由与同一套导航结构。
- [ ] 首页任一状态只有一个视觉上最突出的主动作。
- [ ] 无作品用户无需寻找“创建项目”，可以直接输入故事想法。
- [ ] 有作品用户启动后可以一次操作回到最近创作现场。
- [ ] 生成中、失败、离线和余额不足都不暴露内部任务或技术术语。
- [ ] 普通用户顶层导航只有“首页 / 我的作品 / 素材 / 我的”。
- [ ] 余额和账户信息不抢占创作主任务。

## 一句话新书创建

新用户创建作品时只承担两个必须决策：

1. 输入一句故事想法。
2. 从 AI 提供的方向中选择一个。

其余信息提供推荐默认值，用户想控制时再展开。

### 起始想法

页面视觉中心固定为：

> 你想写一个什么故事？

唯一必填项是“一句话描述你的故事”。输入内容自动保存在本地，余额不足、关闭页面或充值跳转后都不能丢失。

辅助入口：

- 帮我随机想一个。
- 从热门题材开始。
- 我想多说一点。

“我想多说一点”默认折叠，可选内容包括：

- 题材偏好，默认由 AI 判断。
- 主角想法，默认由 AI 设计。
- 想要的阅读感觉，例如紧张刺激、轻松爽快、温暖治愈、悬念重重或热血成长。
- 不希望出现的内容，例如不要后宫、不要系统流、不要太虐。

这些内容都不能成为继续创建的前置条件。

### 三个故事方向

AI 根据起始想法生成三个真正不同的故事方向，而不是只替换书名。每个方向至少展示：

- 临时书名。
- 一句话亮点。
- 主角身份。
- 核心矛盾。
- 整体阅读感觉。
- 大致发展方向。
- 推荐篇幅。

用户的唯一主动作是“就写这个”。次要操作为“换一批”“按我的意见调整”和“返回修改想法”。

换一批或重新调整如果会产生消费，必须在操作前展示预计费用。

### 作品确认卡

用户选择方向后，只展示一张可理解的确认卡：

- 推荐书名。
- 一句话简介。
- 主角。
- 核心冲突。
- 故事感觉。
- 预计卷数。
- 预计章节范围。

主按钮是“按这个方向开始创作”。用户可以修改书名、简介、作品篇幅和创作感觉，但不进入专业规划表单。

### 作品篇幅

篇幅是可选调整项，默认使用“标准长篇”。

| 用户选项 | 产品解释 |
|---|---|
| 短篇故事 | 大约 30～60 章，推进集中 |
| 标准长篇 | 大约 80～180 章，结构完整 |
| 超长连载 | 200 章以上，成长和世界展开更充分 |
| 自定义 | 设置大致章节范围 |

用户不直接填写卷数、每卷章节数、字数公式或 Token。具体卷数由系统根据故事结构决定。

### 系统自动决定

普通用户不填写或看到：

- Provider、Base URL、API Key 和模型路由。
- Prompt、temperature、maxTokens 和上下文长度。
- 读者频道内部枚举和叙事参数。
- 卷数计算规则、节奏板槽位和章节合同。
- 自动导演运行方式、审批策略、质量模式和知识库参数。

第一版不提供模型选择或质量档位。系统根据故事方向、规划、正文、状态提取和审校等任务自动选择模型；用户只面对任务结果、预计 0x积分和实际 0x积分。模型选择作为后续扩展，不进入第一版设置。

### 付费与恢复

新书初始化分成五个必须由用户手动确认的付费阶段：

1. 故事方向。
2. 全书骨架。
3. 全部卷规划。
4. 当前剧情阶段。
5. 第一章。

每一步先展示下一步生成内容和预计 0x积分，用户点击“确认并继续”后才发起模型调用。完成后展示本阶段结果和实际消费，再等待下一次确认；不能在用户确认故事方向后自动连续执行其余四步。

初始化阶段统一规则：

- 手动编辑已生成内容不扣费。
- “换一批”“让 AI 调整”和重新生成都会产生新的模型调用并扣费。
- 只要实际发起模型调用就按中转用量计费，所有调用归入当前初始化阶段的消费汇总。
- 余额统一显示为 0x积分，`1 元人民币 = 1 0x积分`；不展示 USD、Quota、Token 或模型倍率。

余额不足时保留所有输入和已选方向，充值成功后返回原位置继续。

四层规划过程按阶段保存。中途退出后显示“作品准备尚未完成，继续准备作品”，从最后成功保存的阶段继续。已经保存的阶段不重新生成；正在生成但本地未完整接收的阶段按中转现有能力处理，不能承诺取回原请求结果。

### 验收规则

- [ ] 创建新书只有“一句话想法”和“选择故事方向”两个必需决策。
- [ ] 题材、主角、阅读感觉、内容排除和篇幅都有可用默认值。
- [ ] 三个候选方向在核心冲突或发展路径上有实质差异。
- [ ] 选择方向后不展示专业规划表单。
- [ ] 用户不需要设置卷数、模型、Prompt 或运行模式。
- [ ] 第一版没有模型选择入口。
- [ ] 故事方向、全书骨架、全部卷规划、当前剧情阶段和第一章分别等待用户确认。
- [ ] 每个阶段在调用前显示预计 0x积分，调用后显示实际 0x积分。
- [ ] 输入、候选选择和规划阶段都可以在退出、充值或异常后恢复。
- [ ] 状态不确定的 AI 请求不会被自动重新提交。
- [ ] 创建完成后默认直接打开第一章正文。

## 新书四层规划合同

新版本创建作品时采用四层规划：

```text
全书方向 -> 全书骨架
全部卷 -> 相对完整的卷规划
当前剧情阶段 -> 详细推进计划
下一章 -> 具体写作任务
```

### 全书骨架

全书骨架负责确定整本小说最稳定的长期方向：

- 核心故事命题。
- 主角最终目标。
- 核心矛盾。
- 主角成长主线。
- 主要对手和压力来源。
- 全书重大转折。
- 结局方向。
- 必须兑现的核心承诺。

### 全部卷规划

开书阶段一次性生成全部卷的相对完整规划。每卷至少确定：

- 本卷在全书中的作用。
- 开始局面。
- 核心目标和主要冲突。
- 主角阶段成长。
- 关键人物和势力。
- 必须兑现的内容。
- 重大转折和卷末高潮。
- 进入下一卷的牵引。
- 预计章节范围。

“全部卷规划”不等于提前生成全部章节标题、场景和写作任务。远期卷允许保留调整空间，但不能只有一句模糊方向；即使是 soft 卷，也必须具备上述卷级战略字段。

### 当前剧情阶段

系统只详细展开当前正在创作的剧情阶段，包括：

- 阶段目标和起止状态。
- 参与角色。
- 冲突升级路径。
- 需要埋下或兑现的线索。
- 本阶段各章的大致职责。
- 阶段结束后形成的新局面。

普通用户界面使用“当前剧情安排”，不要求理解 beat、节奏板或拆章等内部概念。

### 下一章写作任务

系统按需生成下一章的具体写作依据：

- 开始状态。
- 本章目标。
- 必须发生的事件。
- 必须出场的角色。
- 上一章承接点。
- 不能提前发生的内容。
- 结束状态。
- 章末吸引点。
- 建议篇幅。

该任务由后台自动准备，普通用户只点击“继续写下一章”。

### 首次创建顺序

```text
选择故事方向
-> 生成全书骨架
-> 生成全部卷规划
-> 生成第一段剧情详细计划
-> 生成第一章写作任务
-> 生成第一章正文
```

用户不需要逐项审批。准备期间只展示产品化进度；完成后默认进入第一章，用户可以在“故事规划”中查看和修改全书骨架与全部卷安排。

### 变更影响范围

| 变化 | 默认调整范围 |
|---|---|
| 修改局部正文 | 不自动调整规划 |
| 当前章发生局部变化 | 更新下一章任务和必要连续性状态 |
| 当前剧情阶段发生偏离 | 调整本阶段尚未完成的章节 |
| 当前卷目标发生变化 | 调整当前卷，并检查未来卷的承接 |
| 全书核心方向发生变化 | 才允许重建全书骨架和未来卷规划 |

已经完成的章节和卷不得被自动覆盖。重规划只修改尚未完成的未来范围；需要影响已有正文时，必须先说明影响并由用户确认。

### 验收规则

- [ ] 第一章生成前已经存在全书骨架和全部卷规划。
- [ ] 每一卷都具有明确职责、冲突、阶段成长、高潮和下一卷牵引。
- [ ] 不要求开书时生成全部章节标题和任务。
- [ ] 只详细规划当前剧情阶段。
- [ ] 下一章写作任务按需生成。
- [ ] 用户不需要逐项审批四层内部资产。
- [ ] 局部变化默认只影响最小的未来未写范围。
- [ ] 已完成章节和卷不会被重规划自动覆盖。

## 调整后续剧情

普通用户不需要理解 Replan、节奏板失效或卷骨架重建。所有正文偏离计划、用户主动改变方向和规划资产变化，统一通过“调整后续剧情”处理：用户只描述想怎么改，系统判断最小影响范围，并给出一套推荐方案。

### 触发时机

以下情况才检查后续规划，不随每次输入或光标变化实时检查：

- 用户主动点击“我想调整后续剧情”。
- 用户确认了会改变事实的正文修改或 AI 建议。
- 当前剧情阶段或当前卷结束。
- 用户修改全书骨架、卷规划或阶段目标。
- 用户主动执行“检查后续计划”。

未来若启用连续创作，低影响变化自动吸收；中影响变化在当前章完成后暂停；高影响变化必须在下一次付费生成前暂停。第一版逐章确认时，变化在用户启动下一章前完成处理。

### 影响等级

| 等级 | 典型变化 | 默认处理 |
|---|---|---|
| 低 | 文句润色、小型人物或设定事实变化 | 自动更新事实和下一章任务，不中断创作 |
| 中 | 本章关键事件变化、当前阶段推进方式偏离 | 当前章结束后显示简短调整摘要，由用户选择“调整后继续”或“暂时按原计划继续” |
| 高 | 阶段目标、卷目标、核心角色、主线、故事前提或结局变化 | 在下一次付费生成前暂停，显示“查看调整方案” |

### 最小影响范围

| 变化对象 | 默认调整范围 |
|---|---|
| 只改文字表达 | 不改规划 |
| 小型人物或设定事实 | 事实状态与下一章任务 |
| 当前章关键事件 | 下一章任务与当前剧情阶段 |
| 当前阶段目标 | 当前阶段尚未完成的内容 |
| 当前卷目标 | 当前卷尚未完成的内容，并检查未来卷承接 |
| 核心角色或主线 | 当前卷和未来卷 |
| 故事前提或结局 | 未来全书骨架与尚未完成的卷规划 |

已完成章节和已完成卷始终受保护，不得被自动覆盖。需要改动已有正文时，必须作为独立编辑建议呈现并由用户明确确认。

### 调整方案

调整页只需要回答四个问题：

1. 发生了什么变化。
2. 哪些未来内容会受影响。
3. 哪些已有内容会保持不变。
4. 系统建议如何把故事接下去。

默认只展开一套推荐方案。高级选择折叠提供“尽量保留原计划”和“顺势走向更大胆的新方向”，普通用户无需选择规划层级或内部资产。

用户确认后按以下顺序执行：

```text
保存当前规划版本
-> 更新受影响的未来规划
-> 更新当前剧情阶段
-> 作废尚未执行的旧章节任务
-> 生成新的下一章任务
-> 返回原来的章节编辑位置
```

每次调整必须可以查看差异并恢复上一版规划。需要产生费用时，确认前显示本次预计费用；一次确认只创建一个本地操作，重复点击不得重复提交，状态不确定时不得自动重试。

### 示例

如果原计划在第 20 章揭示角色身份，而用户在第 12 章已经确认提前揭示：

- 第 1 至 12 章保持不变。
- 系统把原来第 20 章的揭示任务标记为失效。
- 当前阶段重新安排“揭示后的关系与冲突”。
- 未来卷只在承接受影响时调整。
- 用户确认后直接回到第 12 章，继续生成第 13 章。

### 验收规则

- [ ] 普通用户只看到“调整后续剧情”，不看到 Replan、失效资产或内部规划层级。
- [ ] 系统默认选择最小的未来影响范围。
- [ ] 已完成章节和卷不会被自动改写。
- [ ] 低影响变化不中断创作，中高影响变化只在合适的章节边界暂停。
- [ ] 高影响变化一定在下一次付费生成前完成确认。
- [ ] 调整前保存规划版本，调整后可以查看差异和恢复。
- [ ] 付费调整在执行前显示预计费用，状态不确定时不会自动重新提交。
- [ ] 调整完成后返回用户原来的编辑位置，并给出明确的下一步。

## 单作品文档型创作台

用户进入某一本作品后，默认工作区不是“小说生产控制台”，而是“带有智能作品目录的文本编辑器”。

默认布局遵循三个稳定职责：

```text
左侧作品目录 -> 选择正在查看或编辑的内容
中间内容编辑器 -> 阅读、写作和修改正文或作品资料
右侧 AI 抽屉 -> 只在需要时提供与当前内容相关的帮助
```

自动导演、AI 修复、质量债务、任务队列、审批点、上下文装配和资产回灌等原有专业能力继续保留，但默认作为后台引擎运行，不再平铺成普通用户需要理解和判断的按钮。

### 左侧作品目录

左侧按用户理解的作品内容组织，而不是按后端模块或生产流水线组织。

默认分组和顺序：

1. 正文
   - 按卷折叠章节。
   - 默认展开当前卷并定位到最近章节。
2. 故事规划
   - 作品方向。
   - 全书大纲。
   - 分卷安排。
   - 当前卷规划。
3. 角色
   - 主要角色。
   - 配角。
   - 角色关系。
4. 世界
   - 世界简介。
   - 核心规则。
   - 势力。
   - 地点。
5. 更多资料
   - 伏笔与线索。
   - 写作素材。
   - 历史版本。
   - 高级设置。

“正文”始终位于最上方，因为继续阅读和写作是打开作品后的最高频任务。世界设定的复杂度根据题材自适应：都市、现实和弱设定题材不要求用户先维护完整世界观。

左侧不能把世界规则、角色资源、质量债务、任务运行、章节合同等所有内部资产平铺成十几个一级项目。低频内容必须分组折叠，专业能力进入高级入口。

### 中间统一内容编辑器

用户从左侧选择任何内容，中间区域都保持“打开一份作品文档”的一致心智：

- 选择章节：阅读和编辑正文。
- 选择作品方向或全书大纲：阅读和编辑故事规划。
- 选择某一卷：阅读和编辑卷规划。
- 选择某个角色：阅读和编辑用户可理解的角色资料。
- 选择世界规则、势力或地点：阅读和编辑对应设定。

不同内容可以使用适合自身的数据结构，但必须共享稳定的页面骨架、保存反馈、历史恢复和 AI 入口。不能让章节、大纲、角色和世界分别变成四套完全不同的后台管理系统。

编辑器至少提供：

- 清晰的当前文档标题和所属位置。
- 自动保存状态。
- 本地保存失败提示与恢复动作。
- 撤销、重做和历史版本。
- 当前内容字数或必要的轻量摘要。

### 右侧按需 AI 抽屉

AI 助手默认可以收起，打开后根据中间正在编辑的内容提供少量上下文动作。

正文场景：

- 一个“你希望这章怎么调整”的自然语言输入框。
- “更精彩”“更自然”“加快节奏”“加强情感”“修正前后矛盾”等少量快捷意图。
- 用户说不清时可以直接输入“读起来不对”，由 AI 结合当前章节判断修改方向。

大纲场景：

- 完善大纲。
- 调整故事节奏。
- 补充冲突。
- 根据大纲规划分卷。

角色场景：

- 完善角色。
- 检查人物动机。
- 设计或梳理角色关系。

世界场景：

- 完善世界规则。
- 检查设定冲突。
- 补充势力、地点或故事舞台。

普通用户不需要判断应该打开自动导演、Creative Hub、AI 修复还是质量工作台。系统根据当前内容选择内部能力，对外统一表达为“AI 帮我写”。

### AI 内容写入边界

AI 不得在用户无感知的情况下直接覆盖现有正文、大纲、角色或世界资料。

#### 章节完成后的三个入口

章节生成完成后，编辑器底部只突出：

- 主按钮：“这章可以，继续下一章”。
- 次按钮：“AI 帮我改”。
- 更多菜单：“重新生成整章”“查看历史版本”。

正文始终可以直接编辑，不设置单独的编辑模式，也不把润色、扩写、缩写、修复和审校同时平铺成一排按钮。

#### 用户手动修改

- 手动编辑、自动保存、采用候选稿和恢复版本都不调用 AI，因此不扣费。
- 输入过程持续自动保存，但自动保存不为每次按键创建历史版本。
- 用户手动修改后，主按钮改为“保存当前修改并继续下一章”。
- 下一章以用户当前保存的正文为创作基线。

#### AI 帮我改

调用前展示预计 0x积分，用户确认后才发起模型调用。AI 修改结果保存为独立候选稿，默认展示修改说明、变化位置和完整候选正文，不直接覆盖当前正文。

候选稿只有三个主动作：

- “采用这版”：先保存当前正文版本，再让候选稿成为当前正文；采用动作本身不扣费。
- “继续调整”：用户补充要求并发起新的付费调用。
- “保留原文”：当前正文不变化，但已经产生的模型消费不会退回。

候选稿在用户采用或放弃前持久化保存。关闭页面或程序异常后可以回到同一个候选现场。

#### 整章重新生成

整章重新生成放在“更多”中。执行前明确说明：

- 原版本会保留。
- 本次会产生新的 AI 消费。
- 新结果会成为独立候选版本。
- 用户确认采用后才替换当前正文。

用户可以附加一句重写要求。生成后提供“使用新版本”“保留原版本”和“查看两版差异”，不能自动覆盖。

#### 自动保存与历史版本

自动保存负责防止输入丢失；历史版本负责用户主动回退，两者必须分开。

关键版本节点：

- 初次生成完成。
- 用户确认手动修改。
- 采用 AI 调整结果。
- 采用整章重新生成结果。
- 确认当前章并进入下一章。
- 从历史版本恢复。

版本名称使用“初次生成”“你的修改”“AI 调整”“重新生成”“章节确认版本”等用户语言，不要求用户理解 `v1`、`v2`。恢复旧版本时创建新的当前版本，不删除恢复前内容。

#### 计费与异常

- 初次生成、AI 调整、继续调整、续写和整章重生成只要实际调用模型就会扣费。
- 用户放弃 AI 结果或认为效果不明显，也不退回已经发生的调用消费。
- 一章的多次操作统一汇总为“本章累计消费”，调用级明细只在展开对账时显示。
- AI 调整断网时原正文不变，已接收候选内容保存为临时稿；“继续完成调整”是新的付费调用。
- 余额不足时保存修改要求，充值后返回原位置。
- 不执行用户不可见的自动重试；状态不确定时先查询余额和消费记录。

#### 修改已确认的旧章节

用户可以返回修改已确认章节。文句和错字修改不阻止继续创作；人物身份、关键事件、人物关系或结局方向等变化，在下一次付费生成前提示“建议先检查后续计划”。

“检查后续计划”属于新的 AI 调用，必须显示预计 0x积分并由用户确认，不能在后台静默扣费。

验收规则：

- [ ] 正文始终可编辑，手动编辑和保存不扣费。
- [ ] 章节完成后只突出继续下一章、AI 帮我改和更多菜单。
- [ ] AI 修改和整章重生成始终先产生候选稿，不直接覆盖当前正文。
- [ ] 用户未点击“采用这版”时，当前正文保持不变。
- [ ] 采用、放弃和恢复版本本身不调用 AI。
- [ ] 自动保存不会产生大量历史版本。
- [ ] 关键节点自动保存可恢复版本，恢复旧版本不删除当前版本。
- [ ] 候选稿在关闭页面或程序异常后仍可恢复。
- [ ] 调用前显示预计 0x积分，调用后计入本章累计消费。
- [ ] 放弃 AI 结果不会删除消费记录。
- [ ] 后台任务不能静默覆盖用户正在编辑的正文。
- [ ] 重复点击不会创建重复请求，状态不确定时不会自动重新提交。

### 逐章确认与阶段审校

C 端默认不要求用户在每章生成后处理审校、修复、质量债务和导演消息。每章完成后的主流程只保留阅读、修改和继续创作。

每章生成后静默完成：

- 正文非空、截断、异常格式和保存状态等确定性基础校验。
- 当前章节版本保存。
- 下一章所需事实和连续性状态准备。
- 人物、世界、伏笔等资产增量同步或建立可恢复的后台同步任务。

这些动作不形成用户待办。深度 AI 审校默认不放在单章热路径中，由用户在剧情阶段或整卷结束时决定是否执行。

#### 默认方式：逐章确认

第一章生成完成后，编辑器底部只突出：

> 这章可以，继续写第二章

用户点击后：

1. 将当前版本保存为下一章的创作基线。
2. 准备下一章必需的事实和连续性状态。
3. 自动准备并生成下一章。
4. 用户停留在同一个创作台，不跳转到任务、审核或消息页面。

“这章可以”不锁死章节，用户以后仍可回来修改。它只表示后续生成以当前版本为依据。正文始终可直接修改，辅助操作只保留“AI 帮我改”和更多菜单。

#### 可选“写完这一段”

逐章确认仍是默认方式。用户看过下一段名称、章节范围和目标后，可以只写下一章，也可以一次授权写完当前剧情阶段剩余章节。

连续创作只由本地持久化批次顺序启动现有逐章操作。每章独立生成、计费和保存；用户暂停时写完当前章再停止，断网、退出或结果不确定时保存恢复点，不自动重放中转请求。它不得跨越当前阶段边界。

#### 费用提示与消费记录

逐章确认时，“继续写下一章”附近只显示下一章的预计 0x积分范围。用户不需要理解 Token、模型倍率或内部计量单位。

统一规则：

- 逐章确认只授权下一章及其必要状态同步的消费。
- 下一章任务、正文生成、必要状态提取和结构化整理等模型调用统一汇总为本章费用。
- 中转按实际调用量扣费；只要产生模型调用就会消费 0x积分。
- 余额不足时保存当前章节和恢复位置，充值成功后返回原运行继续。
- 剧情阶段或整卷审校属于新的付费操作，必须单独展示预计费用并由用户确认。
- 后台必要的状态抽取和资产同步计入当前创作操作的总消费，不能形成没有上限的隐藏调用。
- 网络中断时保留已接收正文；状态不确定的请求不自动重新提交。
- “继续完成本章”使用已有正文发起新的续写请求，并计入当前章节总消费。
- 用户明确要求重新生成时创建新的消费尝试，并再次说明费用。
- 完成、暂停或中断后展示本次实际总消费。
- 产品统一显示 0x积分，`1 元人民币 = 1 0x积分`，不展示中转 Quota 或上游币种。
- 多次调用的技术明细用于对账，普通界面默认只显示本章总消费。

当前中转不能执行操作级消费上限，因此连续创作确认区只展示当前余额和历史费用参考，不能承诺最高总价。若中转未来补齐请求幂等、结果恢复和消费上限，应在保持逐章计费边界的前提下重新评审更强的自动恢复能力。

#### 剧情阶段和卷末审校

到达当前节奏段时，面向普通用户表达为：

> 这一段剧情已经完成。

提供：

- 检查这一段剧情后继续。
- 暂不检查，直接继续。

卷末表达为：

> 第一卷已经完成。

提供：

- 检查本卷并准备下一卷。
- 跳过检查，直接开始下一卷。

阶段审校统一检查多章连贯性、人物行为、世界规则、节奏、重复、伏笔和下一阶段承接。检查结果收敛成整体结论、具体位置和一个推荐动作，不拆成多个需要用户调度的修复任务。

#### 创作进度边界

原“创作消息”不再承担必需操作。它改为只读的“创作进度”，记录章节完成、生成中断、阶段完成、暂停和恢复等历史。

真正需要用户确认的动作必须出现在当前正文或阶段结束位置，不能要求用户前往消息列表寻找不可点击的状态。

验收规则：

- [ ] C 端默认生成计划不在每章后强制启动深度 AI 审校。
- [ ] 每章完成后只有一个“确认当前章并继续下一章”的主动作。
- [ ] 用户确认章节后不离开当前创作台。
- [ ] 默认显示“只写下一章”，并提供可选“写完这一段”；连续模式可暂停且不跨阶段。
- [ ] 阶段或卷末审校单独展示预计费用并由用户确认。
- [ ] 完成、暂停或中断后可以查看本次实际总消费。
- [ ] 剧情阶段和卷末都允许用户选择检查或跳过。
- [ ] 跳过阶段审校不会伪装成错误或产生待处理消息。
- [ ] “创作进度”中的历史状态不承担必需操作。
- [ ] 所有必要确认都在对应章节或阶段结束位置完成。

### 本地作品与换账号

作品正文、规划、草稿和版本默认保存在本机，并按登录账号隔离：

- 同一账号在同一台电脑重新登录后继续看到原作品。
- 换成另一个账号后，原账号作品仍保留，但新账号看不到。
- 退出登录不删除作品。
- 换账号前自动保存正文；如果正在生成，先让用户结束当前创作并保留临时草稿。
- 删除某账号的本地作品是单独操作，不能混入退出登录。
- 同一账号换电脑后不会自动同步作品，使用本地备份包恢复。

第一版提供：

- 导出小说。
- 创建本地备份包。
- 从备份包恢复。
- 打开备份目录。

验收规则：

- [ ] 同机多账号作品互相不可见且不会互相覆盖。
- [ ] 退出、重新登录和换账号不会删除本地作品。
- [ ] 旧账号生成回调不能写入新账号资料域。
- [ ] 备份包可以在另一台电脑恢复作品。
- [ ] 产品不暗示已经提供正文云同步。

### 顶部操作

作品创作台顶部默认只保留：

- 返回首页。
- 当前作品名称。
- 自动保存状态。
- “AI 帮我写”。
- 更多。

“更多”可以承载导出、作品设置、历史版本和高级入口。生成、修复、跟踪、重规划、执行、审校和模型状态不得同时平铺在顶部。

### 专业状态的 C 端表达

| 内部能力或状态 | 普通用户表达 |
|---|---|
| AI 修复 | 帮我修改 |
| 自动导演跟踪 | AI 正在维护故事一致性 |
| 质量债务 | 发现需要检查的内容 |
| 任务中心 | 创作进度 |
| 重规划 | 调整故事方向 |
| 审批点 | 低风险自动继续，高影响变化才请求确认 |
| 运行日志 | 默认隐藏，需要诊断时导出 |
| Prompt 和模型路由 | 由系统自动处理，第一版不进入用户设置 |
| 资产回灌 | 作品资料已同步 |
| Checkpoint | 已自动保存 |

状态主要用于说明发生了什么，不能把每一种状态都做成要求用户判断的操作按钮。任一时刻只给出一个推荐主动作；局部质量问题不能伪装成整本小说失败。

### 状态适配

| 作品状态 | 创作台默认表现 |
|---|---|
| 尚未生成第一章 | 中间显示开篇准备结果和“开始写第一章” |
| 正在生成章节 | 中间逐步展示正文和通俗生成阶段 |
| 章节已完成 | 打开正文编辑器，推荐“继续写下一章” |
| 生成中断 | 保留现有正文，只显示一个恢复主动作 |
| 离线 | 正常编辑本地内容，AI 抽屉说明联网后可用 |
| 余额不足 | 正常编辑，触发 AI 操作时充值并返回原位置 |

### 验收规则

- [ ] 用户进入作品后默认看到正文目录和内容编辑器，不先看到状态控制台。
- [ ] 左侧一级分组不超过“正文 / 故事规划 / 角色 / 世界 / 更多资料”。
- [ ] 章节、大纲、分卷、角色和世界资料共享一致的文档编辑骨架。
- [ ] AI 助手可以收起，并根据当前内容提供上下文动作。
- [ ] 普通用户界面不出现自动导演跟踪、质量债务、Checkpoint、Prompt、模型路由等内部术语。
- [ ] 顶部不形成生成、修复、跟踪、审校和重规划按钮墙。
- [ ] 原有专业能力仍可由后台调用，并保留高级或诊断入口。
- [ ] 任一作品状态只有一个推荐主动作。

## 禁止做法

- 要求新手自己判断是否应该重规划、修章节、重跑角色或修改世界观。
- 给用户展示内部重构、迁移或历史实现叙述作为产品说明。
- 把 Creative Hub 扩展成泛聊天工具，而不推进小说完成。
- 在世界库列表直接堆叠地理、文化、宗教、经济、历史等长字段，迫使用户像审表格一样理解世界。
- 在世界工作台概览页重复结构化设定页的表单和长文本编辑区，让用户无法区分“理解世界”和“维护字段”。
- 在小说页继续使用“绑定世界观”作为主入口，把外部世界库样本、本书世界副本和 StoryWorldSlice 裁剪结果混成一个概念。
- 在生成注入提示中继续写“未绑定世界观”，让用户误以为没有选择旧下拉就无法生成；正确表达应是“没有可用的本书世界上下文，生成会先根据小说基础信息推进”。

## 失败模式

- 用户看到很多按钮但不知道下一步：检查是否缺少单一推荐动作和原因。
- 用户以为任务卡住：检查前端是否展示真实产物进度、阻塞原因和恢复动作。
- 世界观参与生成链很弱：检查世界库样本、小说世界副本、StoryWorldSlice 和 `WorldContextGateway` 是否被清楚区分，生成链是否绕过了统一门面。
- 角色生成需要给新手一个低成本控制点：默认基于本书世界生成，同时允许选择势力倾向和世界规则合规检查，而不是要求用户手写完整人物背景。
- 可视化曲线一进入页面就能拖拽：这会把“浏览走势”误变成“写入锚定”，应改为只读展示 + 显式编辑入口，并为编辑现场补齐叙事上下文。
- 自动导演创建被做成弹窗套弹窗：方向候选、修订和执行进度需要足够纵向空间，也需要刷新后恢复同一现场；应使用独立页面和任务参数，而不是继续把长流程塞进创建表单弹窗。
- AI 判断失败后加了关键词兜底：应修 AI schema、prompt、上下文和评估，而不是让产品逻辑退回硬编码。
