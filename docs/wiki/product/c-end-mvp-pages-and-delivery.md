# C 端 MVP 页面清单与实施路线

## 背景

旧版产品围绕专业生产流水线组织页面，暴露任务、导演、修复、模型、质量和系统状态。C 端第一版必须改为一条普通用户可以独立完成的主链：安装、登录、充值、创建作品、完成初始化、逐章创作并完成前三章。

本文冻结第一版页面边界、导航结构、端到端链路、实施顺序和总验收目标。具体视觉规范以新手优先产品原则为准，认证、中转、计费和本地资料域以桌面端用户 Token 方案为准。

## 第一版总目标

第一版完成标准不是“旧功能全部迁移”，而是：

> 一名不了解模型、Prompt、小说规划和任务系统的用户，可以独立安装软件，注册或登录，完成充值，从一句话创建新书，并在不接触专业状态的情况下完成前三章。

## 全局导航

主应用只保留四个一级入口：

1. 首页。
2. 我的作品。
3. 创建作品。
4. 我的。

进入作品后切换为作品内导航，不继续展示旧 B 端后台菜单。

## 七个核心页面

| 页面 | 核心职责 | 必须包含 | 禁止暴露 |
|---|---|---|---|
| 启动与登录 | 单窗口启动、注册、登录和身份恢复 | 保持登录、忘记密码、网络与启动错误恢复 | 命令行、端口、数据库、Provider、Token |
| 首页 | 根据用户状态给出唯一推荐下一步 | 创建第一部小说、继续作品、恢复生成、充值后继续、离线编辑 | 系统监控、任务统计、模型用量仪表盘 |
| 我的作品 | 查找和继续本地作品 | 作品名、当前章节、当前卷、最近编辑时间、继续创作 | 团队协作、云同步和后台任务状态 |
| 创建新书 | 完成五阶段初始化 | 故事方向、全书骨架、全部卷规划、当前剧情阶段、第一章 | 专业规划表单、模型与运行参数 |
| 单作品创作台 | 完成逐章阅读、编辑和 AI 创作 | 作品目录、统一编辑器、AI 候选稿、版本、逐章确认、阶段审校 | 导演跟踪、质量债务、AI 修复和任务控制台 |
| 我的账户 | 管理用户、0x积分和充值 | 余额、充值、消费记录、充值记录、换账号、退出登录 | Quota、Token、模型倍率和中转请求 |
| 本地数据与设置 | 管理本地数据和基础桌面设置 | 导出、备份、恢复、备份目录、更新、字体主题、诊断、删除本地数据 | Provider、Prompt、RAG、Webhook、数据库和工作流配置 |

## 页面内状态

以下能力不创建独立一级页面：

| 能力 | 产品载体 |
|---|---|
| AI 帮我改 | 创作台按需抽屉 |
| 历史版本 | 创作台侧边抽屉 |
| 充值 | 账户页或当前付费动作中的充值浮层 |
| 消费明细 | 账户页抽屉 |
| 生成中断 | 当前编辑器状态卡 |
| 余额不足 | 当前操作位置的充值浮层 |
| 创作进度 | 创作台只读历史抽屉 |
| 导出 | 作品更多菜单 |
| 调整后续剧情 | 当前章节或故事规划中的流程面板 |

任何需要用户处理的动作都必须出现在当前内容和当前步骤旁边，不能要求用户前往“创作消息”或任务列表寻找不可点击状态。

## 三条端到端主链

### 新用户

```text
启动
-> 注册
-> 自动登录
-> 创建作品
-> 故事方向
-> 全书骨架
-> 全部卷规划
-> 当前剧情阶段
-> 第一章
-> 单作品创作台
```

五个初始化阶段分别展示预计 0x积分，并在用户确认后发起调用；不能自动连续扣费。

### 返回用户

```text
启动
-> 加密 Token 恢复登录
-> 首页显示最近作品或未完成操作
-> 继续创作
-> 阅读或修改当前章
-> 确认并生成下一章
```

### 余额不足

```text
用户确认付费 AI 操作
-> 发现余额不足
-> 微信扫码充值
-> 按 orderNo 恢复并查询原订单
-> 0x积分到账
-> 返回原操作位置
-> 用户再次确认并继续
```

支付成功不能直接替用户发起新的模型调用。

## 实施路线

### 阶段 0：正式 C 端运行边界

范围：

- 单窗口静默启动。
- 正式构建只允许中转 AI。
- 新旧数据域物理隔离。
- 本机 API 访问保护。
- C 端前后端路由白名单。
- 正式包不能进入旧 B 端页面和直连模型路径。

完成标准：

> 双击正式 EXE 后只打开一个产品窗口，用户只能进入新 C 端链路。

### 阶段 1：账号、资料域和充值

范围：

- 同步注册、登录和保持登录。
- Token 安全存储和强制登录门。
- 稳定用户 ID 到本地匿名资料域的映射。
- 换账号和退出登录。
- 0x积分余额、微信充值、订单恢复和消费记录。

完成标准：

> 用户可以注册、登录、充值、退出和重新登录；同机不同账号的数据不会互相显示或写入。

### 阶段 2：本地作品数据基础

范围：

- 新作品、规划、章节和创作操作。
- 当前工作草稿、AI 候选稿和不可变历史版本。
- 自动保存。
- 本地导出、备份包和恢复。

完成标准：

> 即使暂时不接入 AI，用户也能创建作品、编辑正文、切换账号、关闭重开并恢复内容。

### 阶段 3：新书五阶段初始化

范围：

- 一句话想法和方向候选。
- 故事方向、全书骨架、全部卷规划、当前剧情阶段和第一章。
- 每阶段手动确认、预计积分、实际积分、中断和充值恢复。

完成标准：

> 新用户可以从一句话走到第一章，每一个付费阶段都由用户确认。

### 阶段 4：创作台核心

范围：

- 左侧作品目录和中间统一编辑器。
- 自动保存和本地保存错误恢复。
- 下一章任务、流式正文、逐章确认和本章消费汇总。
- 中断后保存已接收正文并从已有内容继续。

完成标准：

> 用户可以从第一章走到第三章，不需要理解任务、导演、审校或模型。

### 阶段 5：AI 修改与版本

范围：

- “AI 帮我改”和少量快捷意图。
- 候选稿、采用、继续调整和保留原文。
- 整章重新生成。
- 历史版本和非破坏性恢复。
- 本章累计消费。

完成标准：

> AI 不能在用户未确认时覆盖正文，所有付费调用都有预计和实际消费反馈。

### 阶段 6：阶段审校与后续调整

范围：

- 当前剧情阶段和整卷结束判断。
- 用户选择检查或跳过。
- 用户描述后续变化。
- AI 判断最小未来影响范围。
- 规划版本、差异和下一次生成前的高影响确认。

完成标准：

> 用户不需要理解审校和重规划，也能检查多章质量和调整后续剧情。

### 阶段 7：正式发布收口

范围：

- 离线状态和全部异常文案。
- 安装、升级、卸载与备份恢复验证。
- 代码签名、更新检查和日志脱敏。
- 正式构建删除或拒绝全部旧 B 端入口。
- 安装包端到端烟测。

完成标准：

> 全新 Windows 用户可以独立安装、注册、充值并完成前三章，重启、断网和换账号不会破坏作品。

## 阶段门禁

- 阶段 0 未完成前，不实现正式付费调用。
- 阶段 1 未完成前，不把作品绑定到临时账号字段。
- 阶段 2 未完成前，不接入会写正文的 AI 流程。
- 阶段 3 主链未走通前，不开发阶段审校、后续调整或高级入口。
- 阶段 4 的逐章生成、恢复和计费边界稳定后，连续创作只能复用同一逐章链路，并限制在当前剧情阶段内。
- 每个阶段必须先通过对应端到端验收，再进入下一个阶段。

## 第一版明确不做

- 模型选择和质量档位。
- 用户 API Key、Provider 和 BaseURL。
- 跨剧情阶段或无人值守的整书连续创作。
- 正文云同步。
- 旧作品迁移。
- 手机端和团队协作。
- 社区、作品发布和内容市场。
- 会员订阅和自动续费。
- 专家模式、Prompt 编辑和工作流编辑。
- 任务中心、系统监控和专业运行控制台。
- 图片、语音和视频生成。

## MVP 总验收

- [ ] 正式 EXE 只有一个产品窗口，不出现技术控制台。
- [ ] 未登录不能进入主应用，保持登录后可自动恢复。
- [ ] 新用户完成五阶段初始化后进入第一章。
- [ ] 每个付费调用前有明确确认，完成后可查看实际 0x积分。
- [ ] 用户可以完成前三章并逐章确认。
- [ ] 正文可直接编辑，AI 修改先生成候选稿。
- [ ] 重启和断网不会丢失本地已保存正文。
- [ ] 同机多账号作品互相隔离。
- [ ] 充值订单可恢复，支付金额与到账积分满足 1:1 合同。
- [ ] 用户可以导出和备份作品。
- [ ] 第一版界面不存在模型、Provider、Prompt、任务和导演设置。
