# 技术债务清单

> 最后更新：2026-07-29

## 高优先级

### 2026-07-28 商业授权与 AGPL 上线路线未确认

- **位置**：`LICENSE`、`NOTICE`、`CLA.md`、桌面发布物与未来中转 SaaS
- **问题**：原项目采用 `AGPL-3.0-only` 并明确写有服务型商用需另行授权；当前没有可验证的书面商业许可，也没有经过律师确认的 AGPL 履约上线方案。
- **影响**：删除原作者地址或更换品牌不能产生闭源商业化权利；在解决前收费发布桌面版或 SaaS 存在重大版权与许可证风险。
- **优先级**：P0
- **处理**：先核实 `NOTICE`、Git 作者、仓库账号和历史贡献者的权利链；再取得覆盖桌面端、中转服务、修改、收费与再分发的书面授权，或完成律师确认的 AGPL 开源履约路线。
- **关联**：[商业 SaaS 风险审计](wiki/security/commercial-saas-risk-audit.md)

### 2026-07-28 正式更新地址和 Windows 签名材料尚未配置

- **位置**：`consumer-release.json`、桌面发布工作流、自有账号 API、自有 AI 中转、自有更新站与 Windows 签名
- **问题**：自有账号中转 `https://api.0xkey.cn`、模型中转 `https://api.0xkey.cn/v1` 已成为桌面发布默认值，C 端统一出口、HTTPS 域名白名单、旧后台停用和无签名正式版阻断已经落地；但正式更新 URL 和 Windows 签名证书仍未配置。
- **影响**：没有真实材料时只能构建 Beta/本地验证包，不能完成可信安装、自动更新和真实外联验收。
- **优先级**：P0
- **处理**：提供自有 HTTPS 更新地址和受保护的 Windows 签名材料，通过正式发布工作流生成签名安装包，再在全新 Windows 环境验证安装、升级、回滚、卸载和实际域名访问。
- **关联**：[完整改造总纲：阶段 7](wiki/architecture/local-exe-saas-rebuild-plan.md#阶段-7正式发布收口)

### 2026-07-28 法务文本与中转账号闭环未完成

- **位置**：隐私政策、用户协议、中转账号注销、退款和人工支持
- **问题**：产品内已经解释本地数据和中转数据边界，并支持删除当前账号的本机资料域；但商业主体、联系方式、保存期限、账号注销、退款条件和人工支持仍缺少可执行的正式流程。
- **影响**：本机数据删除不能替代中转账号注销；即使软件功能可用，也不满足真实收费发布的用户权益与合规要求。
- **优先级**：P0
- **处理**：由实际运营主体和法务冻结隐私政策、用户协议和退款规则；中转提供账号注销接口或人工闭环，并在客户端明确入口、处理时限与联系方式。
- **关联**：[完整改造总纲：商业门槛](wiki/architecture/local-exe-saas-rebuild-plan.md#23-商业安全和合规门槛)

### 2026-07-28 中转 AI 请求缺少幂等与结果恢复契约

- **位置**：`server/src/relay/llm/`、章节生成、规划、审校和消费对账流程
- **问题**：当前接口文档没有 AI 请求幂等、运行状态查询、结果取回、流式断点续传或操作级消费上限接口；消费日志可以按请求编号查询，但不能取回生成内容。
- **影响**：请求发送后断网时无法严格判断并恢复原结果，自动重试可能形成新的模型消费；多章连续创作也无法可靠限制最高消费。
- **优先级**：P0
- **处理**：第一版只开放逐章确认；流式正文持续保存到本地，状态不确定时禁止自动重新提交，中断后从已有正文创建新的续写请求并明确计入消费。充值订单仍按 `orderNo` 完整恢复。
- **关联**：[桌面端用户 Token 与中转方案](wiki/architecture/desktop-user-token-auth-plan.md#15-现有中转契约下的重复请求边界)

### 2026-07-28 0x积分与中转 Quota 的 1:1 合同尚未联调

- **位置**：中转余额、消费日志、微信充值、本机用量适配和账户 UI
- **问题**：产品已确定 `1 元人民币 = 1 0x积分`，代码已经在付款前强制校验订单 `money === amount`，并提供真实订单/模型对账脚本；但尚未用真实已支付订单与真实模型调用完成生产留证。
- **影响**：如果只在前端改名，可能出现支付金额、到账积分、消费记录和余额变化不一致，直接影响用户信任和财务对账。
- **优先级**：P0
- **处理**：用 `pnpm run verify:relay-contract:live` 查询一笔真实已支付小额订单，再显式开启一次最小真实模型调用，验证余额下降、累计消费上升且出现消费日志；不一致时禁止自动继续付费创作。
- **关联**：[桌面端用户 Token 与中转方案](wiki/architecture/desktop-user-token-auth-plan.md#16-充值闭环)

### 2026-07-28 中转缺少任务级计价预估契约

- **位置**：`server/src/modules/consumerSetup/application/setupService.ts`、中转模型路由和未来章节生成
- **问题**：中转接口没有按任务预估积分、模型费率快照或消费上限契约，客户端不能在首次同类调用前计算可靠区间。
- **影响**：当前只能在产生过真实历史操作后展示最近十次同类消费范围；首次调用只能明确说明按实际用量计费，尚未完全满足每次调用前展示数值预估的产品目标。
- **优先级**：P0
- **处理**：中转增加根据任务类型、模型和预计输入/输出量返回积分区间的接口，并让实际消费记录引用同一费率快照；接口冻结前禁止硬编码固定价格。
- **关联**：[完整改造总纲](wiki/architecture/local-exe-saas-rebuild-plan.md#17-0x积分充值和消费)

## 中优先级

### 2026-07-28 第三方依赖许可证信息仍需人工复核

- **位置**：发布流水线生成的 `bom.cyclonedx.json` 与 `third-party-licenses.json`
- **问题**：流水线已经记录 832 个生产依赖并生成 SBOM，但部分包管理元数据可能缺少标准许可证标识或显示 `NOASSERTION`。
- **影响**：自动生成清单只能证明依赖可追踪，不能自行证明所有依赖都满足目标商业分发方式。
- **优先级**：中
- **处理**：正式发布前逐项核验信息缺失、非宽松或带附加义务的依赖，保存许可证文本和法务结论，并把审查结果绑定到发布版本。
- **关联**：[完整改造总纲：阶段 7](wiki/architecture/local-exe-saas-rebuild-plan.md#阶段-7正式发布收口)

### 2026-07-28 Node 与 Electron 的 SQLite 原生模块 ABI 无法共用

- **位置**：`better-sqlite3`、服务端快速测试与 Electron 桌面运行时
- **问题**：当前安装目录中的 `better-sqlite3` 为 Electron ABI 133 编译，命令行 Node 24 需要 ABI 137；直接重编译会让另一侧失效。
- **影响**：加载真实 Prisma SQLite 客户端的完整 Node 快速测试集无法在同一个依赖目录运行；不加载原生数据库的 32 项 C 端聚焦回归、两套 Schema 校验和桌面类型检查仍可运行。
- **优先级**：中
- **处理**：为 Node 测试和 Electron 打包使用隔离的原生依赖暂存目录或分别构建缓存，并在 CI 中各自执行真实 SQLite 烟测。
- **关联**：桌面打包作用域兼容、C 端本地数据域

## 低优先级

### 2026-07-28 单文件本地备份暂限 512 MB

- **位置**：`desktop/src/runtime/profileBackup.ts`
- **问题**：第一版备份包为带哈希校验的 gzip 单文件，会在内存中组装数据库和本地素材，因此主动限制为 512 MB。
- **影响**：当前纯文本小说和少量素材不受影响；未来若开放大量图片、音频或视频，本地备份需要改为流式归档，不能继续提高内存上限。
- **优先级**：低
- **处理**：在图片等大体积能力进入正式 C 端前，改为流式 ZIP/TAR 写入和逐文件流式校验。
- **关联**：C 端全新本地数据域

### 2026-07-17 兼容环境变量仍使用历史命名

- **位置**：`AI_NOVEL_*` 兼容环境变量
- **问题**：部分本地运行和发布配置仍保留历史环境变量名。
- **影响**：这些名称不产生网络请求，也不会通知原作者，但增加配置理解成本。
- **优先级**：低
- **关联**：后续在完成 C 端新运行时切换后统一迁移。

## 已解决

### 2026-07-29 Beta 安装包不再生成空中转策略

- 根因是 Beta 打包在未提供环境变量时允许把账号和模型中转地址写成 `null`，导致安装后注册在请求发出前直接失败。
- 桌面发布现在从 `desktop/config/consumer-release.defaults.json` 读取自有账号和模型中转地址，环境变量仍可覆盖。
- 修正版安装包及解包后的 `consumer-release.json` 已确认包含 `https://api.0xkey.cn`、`https://api.0xkey.cn/v1` 和对应 HTTPS Origin 白名单。

### 2026-07-29 注册、登录和专用 Key 生命周期已冻结

- 注册只发送 `username`、`password`、可选 `email` 和可选 `verification_code`，登录只发送 `username`、`password`。
- 产品不再假定注册/登录响应直接携带 Token，而是同步完成登录 Cookie、专用 `0xNovelAgent` Key 查找/创建和明文取回。
- 只复用启用且未过期的产品专用 Key；裸 key 在服务端边界规范为 `sk-`，桌面 Broker 和加密存储拒绝非规范形式。
- 会话恢复使用余额接口重新校准用户身份，注册、登录、余额/日志/充值和三种 AI 输出协议已纳入 `pnpm run verify:relay-contract`。

### 2026-07-28 C 端外部请求、日志和发布构建边界完成本地收口

- C 端服务只开放健康检查和专用 Consumer API，所有 AI 请求强制走自有中转，生产地址受 HTTPS 白名单约束。
- 正式桌面 renderer 不打包旧 B 端路由，C 端后台不启动 RAG、导演、旧任务恢复、Webhook 和其他第三方专业服务。
- 日志统一脱敏和截断，C 端禁止模型请求、响应与完整正文日志。
- 非 Beta 发布没有无签名旁路；发布流水线验证边界并生成 SBOM 和第三方许可证清单。

### 2026-07-17 主仓库与桌面更新源脱离原 GitHub

- 主仓库已切换到私有 Gitee，原 GitHub 只保留为禁止推送的本地 `upstream` 参考。
- 桌面包不再生成指向原 GitHub Releases 的更新配置；只有显式提供自有通用更新地址时才启用自动更新。

### 2026-07-28 原公开站路径与原作者 CLA 链接清理

- 公开站不再硬编码原作者 GitHub Pages、旧仓库路径、canonical、sitemap 或社交分享地址。
- 未配置 `OXNOVEL_PUBLIC_SITE_URL` 时不会生成绝对公开地址；配置后只使用自有站点。
- 删除未使用的第三方 GitHub 星标代理请求，并在站点与桌面发布前执行遗留外联检查。
- Pull Request 模板不再指向原作者 CLA；自有商业授权和 CLA 主体完成前不合并外部代码贡献。
